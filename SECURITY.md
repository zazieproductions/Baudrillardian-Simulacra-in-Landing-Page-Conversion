# Security

THE PRODUCT™ is a static, client-only website. It has no backend, no server,
no database, no authentication, and no collection of user data. This file is
proportionately short because the attack surface is proportionately small.

## Security model

- **Static build.** Everything in `dist/` is generated by Vite from
  `src/` and `public/`. There is no server-side code.
- **No external requests at runtime.** The page loads its own bundle, CSS, and
  self-hosted fonts. It does not call a third-party API on load. (The only
  network activity is the browser fetching the site's own assets.)
- **No user data.** Nothing is persisted to `localStorage` or `sessionStorage`
  by the site itself, and nothing is sent anywhere. The "claim" flow is a
  purely client-side state change.
- **No secrets.** The repo contains no tokens, keys, or credentials. `.env`
  variables are optional and are not required to run.

## What this means

- There is no server to compromise.
- There is no database to leak.
- There are no authenticated endpoints.
- The main risks are the same as for any client-side web app: if a dependency
  has a vulnerability, and if the hosting is compromised.

## Dependency scanning

`npm audit` should be kept clean. The project currently reports
**0 vulnerabilities**. If a high-severity advisory appears for a runtime
dependency, update it and re-run the smoke test; if it's a dev-only
dependency in `scripts/`, assess whether it affects the shipped artifact (it
doesn't, because devDependencies are not bundled).

## Reporting

If you believe you've found a security issue (e.g. a dependency vulnerability,
or an XSS vector via the content layer), please open an issue with the label
`security` and avoid including sensitive details publicly until it's triaged.
Because this is a static site, most findings will be dependency advisories
rather than exploitable bugs in the page itself.

## Do not add

- Do not add a backend, analytics, tracking, or telemetry scripts to the page.
  This is a creative work, not a product collecting data, and it's a security
  (and conceptual) commitment.
- Do not add `localStorage` persistence of user behavior without a clear
  reason and disclosure it in the README.
